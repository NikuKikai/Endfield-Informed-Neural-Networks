# 终末地工厂配平

Vite + React + TypeScript 静态前端。TensorFlow.js 在 Web Worker 中优化稳态配方速率；画布用于查看、聚焦和调整产线图。

```bash
npm install
npm run dev
npm run build
```

## 建模

每条配方的倍率 `x_r ≥ 0` 是待优化变量，表示连续运行的设备当量，允许小数；配方的投入、产出和周期固定。物品速率统一为每分钟。物品 `i` 的净输出为 `N_i = 外部输入_i + Σ(配方产出速率_ir × x_r) − Σ(配方消耗速率_ir × x_r)`。配方比例因此由数据直接保证，图上的连线流量是计算结果，不是额外的优化变量。`可外部输入` 和 `可生产` 是独立属性；禁用产物只禁止其生产，不禁止外部输入。

## 优化

默认让未设目标物品的净输出趋于 0；显式目标用 `(目标值 − 净输出)²`。供给上限、天有烘炉合计最多 12 台，以及效果节点和可兑换物品的欠供，采用单侧平方惩罚；外部输入上限为 0 时直接固定为 0。配方倍率和外部输入每步截断至非负。使用 Adam 反向传播，可在现有结果上继续运行；各项损失和历史曲线用于检查是否真正收敛。循环配方按同一稳态方程求解，无须沿图递归展开。

耗电最小化使用连续倍率乘以配方耗电；界面展示耗电则按每条配方倍率向上取整后计算，发电另计且不参与耗电最小化。武陵调度券按对应物品净输出乘兑换单价求和，以负号加入损失实现最大化。两个权重滑条的内部系数均为显示值乘 `0.1`。启用调度券目标时，未设净输出目标的可兑换物品允许正结余，但欠供仍受惩罚；另有微弱的倍率和外部输入惩罚抑制无意义运行。

## 特殊机制与数据

- 直接通入装置的气体按每台配方效率消耗 `6/分钟`，作为条件输入接入物品节点。
- 散布机以 `30 气体 → 30 气体效果` 建模；效果是独立节点。按一台散布机覆盖最多四台相关设备，将每台配方效率的效果消耗设为 `7.5/分钟`。效果允许正净输出，仅对负净输出惩罚。这是对覆盖数量、设备整数和空间范围的不连续规则的连续近似，并未做精确场地布置校验。
- 实际设备数的取整只用于耗电展示，不进入可微目标。天有烘炉数量上限也用软约束，因此结果仍需检查约束残差。

配方快照来自 [IndustrialPlanner](https://github.com/hsyhhssyy/IndustrialPlanner) 提交 `0dc1269fd7188d1236ece61a46afdd064b7440be` 的注册表。当前 `src/data/registry.json` 有 139 个物品、177 条配方；导入时排除装液体或气体的瓶/罐、净变化为零的搬运配方，以及 `WATER_PURIFIER_NODE_ENTITY_ID` 和扩容反应池的特殊配方。重导入时将上游仓库放在项目根目录的 `.source-IndustrialPlanner`，运行 `node scripts/import-registry.mjs`。最终物流节拍与空间覆盖仍需在游戏或仿真器中核验。
